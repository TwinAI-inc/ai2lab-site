Average Reward Setting for Continuing Tasks

Chapter 10 An Alternative to Discounted Formulation - Sutton & Barto
Why this chapter exists

Everything so far has assumed an episode ends. The pole falls, the lander touches down, the game finishes, and you can total what the agent collected. Now think about a process that never stops: a queue that runs all day, a machine that keeps producing, a recommender serving users for years. There is no final total to compare, because the total is infinite either way.

The usual fix is to discount, multiplying each future reward by a number below one so the sum stays finite. It works, and it hides a problem: you had to invent the discount factor. Nothing in the queue told you it should be 0.9 rather than 0.99, and the two give you different policies. This chapter is about the alternative — measuring the rate of reward instead of the total, so there is no arbitrary number to pick.

The Average Reward Framework

For continuing tasks (tasks with no natural termination), we have traditionally used discount factors γ < 1. However, this approach introduces several problems:

  • The choice of γ is arbitrary and significantly affects the learned policy
  • For long-horizon tasks, γ must approach 1.0, causing numerical instability
  • Discount factors create "nearsighted" behavior where the agent undervalues distant rewards
  • The discount formulation conflates two distinct concerns: the uncertainty of future states and the time preference

Key Insight: Instead of discounting, we can measure performance as the average reward per time step in the long run. This eliminates the need for arbitrary discounting while naturally handling continuing tasks.

The average reward setting defines optimality in terms of the long-run average reward rate, making it particularly suitable for continuing tasks where there's no natural endpoint and we care about steady-state performance.

Core Concepts & Equations

Reading the equations

Three of the four symbols below are doing one job: separating how well the agent does per step from how much better one state is than another. The reward rate r(π) is the first, a single number for the whole policy. The differential value is the second, and it is a difference rather than a total — how much extra reward you collect by starting here rather than in an average state.

If a value ever looked like a strange quantity to you, this is the version where it becomes concrete: it is measured in reward-steps of advantage, and the worked example further down does the arithmetic on a two-state problem you can check by hand.

Average Reward Rate
r(π) = limh (1/h) Σt=1h E[Rt | S0, A0:t-1 ~ π]
The long-run expected reward per time step under policy π

In the average reward setting, we assume ergodicity: starting from any state and following any policy, all states are reachable with positive probability. Under ergodicity, the average reward is independent of the starting state.

Differential Value Function
vπ(s) = Σt=1 E[Rt - r(π) | S0 = s, A0:t-1 ~ π]
Expected sum of differences between rewards and average reward

The differential value function vπ(s) measures how much better or worse it is to start in state s compared to the long-run average. It answers: "How much extra reward do I get by starting here?"

Differential Bellman Equation
vπ(s) = Σa π(a|s) Σs',r p(s',r|s,a)[r - r(π) + vπ(s')]
Bellman equation without discounting
Optimal Bellman Equation
v*(s) = maxa Σs',r p(s',r|s,a)[r - r* + v*(s')]
Bellman optimality equation for average reward
Differential TD Error
δt = Rt+1 - r̄t + v(St+1) - v(St)
TD error using average reward estimate r̄t

R-Learning Algorithm

R-learning is the differential version of Q-learning for the average reward setting. It learns both the average reward rate and the differential action values simultaneously.

R-Learning: Average Reward Update
r̄t+1 = r̄t + β[Rt+1 - r̄t + maxa Q(St+1,a) - maxa Q(St,a)]
Update average reward estimate (β is step size for average reward)
R-Learning: Action-Value Update
Q(St,At) Q(St,At) + α[Rt+1 - r̄t + maxa Q(St+1,a) - Q(St,At)]
Update differential Q-values (α is step size for Q-values)

Key Difference from Q-Learning: R-learning uses (Rt+1 - r̄t) instead of just Rt+1, and no discount factor appears. The algorithm learns what's "better than average" rather than absolute values. The term maxa Q(St+1,a) - maxa Q(St,a) represents the change in the value of the best action.

Discounted vs. Average Reward: A Comparison

Discounted Setting

Return: Gt = Σk=0 γkRt+k+1

Value Function: vπ(s) = Eπ[Gt | St = s]

Pros: Well-studied theory, mathematically convenient, contractive operators guarantee convergence

Cons: Arbitrary γ choice, nearsighted behavior, numerical issues when γ1, conflates time preference with uncertainty

Best for: Episodic tasks, when future truly matters less, finite-horizon problems

Average Reward Setting

Return: Σt=1 (Rt - r(π))

Value Function: vπ(s) = Eπ[Σ(Rt - r(π)) | S0 = s]

Pros: No discounting needed, natural for continuing tasks, avoids γ tuning, focuses on steady-state performance

Cons: Requires ergodicity, more complex convergence analysis, less developed theory than discounted case

Best for: Continuing tasks, long-term optimization, systems with steady-state behavior (control systems, servers, robots)

Numerical Example: Two-State MDP

Problem Setup

Consider a simple continuing task with two states: State A and State B. The agent alternates between them deterministically.

Transition Structure

• From State A: Always transition to State B with reward RA = +2

• From State B: Always transition to State A with reward RB = +4

• This continues forever (continuing task)

Solution Using Average Reward

Step 1: Calculate Average Reward Rate

Since we alternate between states equally:

r(π) = (RA + RB) / 2 = (2 + 4) / 2 = 3.0

The long-run average reward is 3.0 per time step.

Step 2: Calculate Differential Values

For State A, we get reward 2 (which is 1 below average), then move to State B:

v(A) = (2 - 3) + v(B) = -1 + v(B)

For State B, we get reward 4 (which is 1 above average), then move to State A:

v(B) = (4 - 3) + v(A) = 1 + v(A)

Solving this system (substituting first equation into second):

v(B) = 1 + (-1 + v(B)) = v(B)

This is satisfied for any offset. By convention, we set v(B) = 0 (choosing a reference state):

v(B) = 0
v(A) = -1 + 0 = -1
Step 3: Interpretation

• v(A) = -1: Starting in State A is 1 unit worse than the reference

• v(B) = 0: State B is our reference (neutral)

• Both differential values are relative to the average reward of 3.0

• The agent prefers State B over State A by 1 unit

Comparison with Discounted Setting (γ = 0.9)

Discounted Values

For State A:

vγ(A) = 2 + 0.9·vγ(B)

For State B:

vγ(B) = 4 + 0.9·vγ(A)

Solving:

vγ(A) = 2 + 0.9(4 + 0.9vγ(A))
vγ(A) = 2 + 3.6 + 0.81vγ(A)
0.19vγ(A) = 5.6
vγ(A) = 29.47
vγ(B) = 4 + 0.9(29.47) = 30.52

Key Observations

Method v(A) v(B) v(B) - v(A)
Average Reward -1.0 0.0 1.0
Discounted (γ=0.9) 29.47 30.52 1.05

Important: Both methods agree on the relative preference (State B is better), but average reward provides a cleaner interpretation: values are differences from the average rather than discounted sums. As γ1, discounted values, but average reward values remain bounded and interpretable.

When to Use Average Reward Setting

Advantages of Average Reward

Continuing Tasks:
Naturally suited for tasks with no terminal states, like process control, server management, or robot navigation where performance continues indefinitely.

No Discount Tuning:
Eliminates the arbitrary choice of γ, removing a hyperparameter that significantly affects learned behavior and policy quality.

Long-term Optimization:
Focuses on long-run performance without myopic behavior caused by high discounting. All future rewards treated equally.

Numerical Stability:
Avoids numerical issues that arise when γ must be very close to 1 for long-horizon problems. Values remain bounded.

Important Requirement: The average reward setting requires ergodicity – all states must be reachable from all other states under any policy. It's most effective when you care about steady-state performance rather than transient behavior. For episodic tasks or when time preference is important, the discounted setting may be more appropriate.

Differential SARSA & Expected SARSA

The average reward framework can be applied to on-policy methods as well:

Differential SARSA
Q(St,At) Q(St,At) + α[Rt+1 - r̄t + Q(St+1,At+1) - Q(St,At)]
On-policy TD control using the action actually taken
Differential Expected SARSA
Q(St,At) Q(St,At) + α[Rt+1 - r̄t + Σa π(a|St+1)Q(St+1,a) - Q(St,At)]
Uses expected value over next actions instead of sampled or max

Algorithm Choice: Use Differential SARSA when learning on-policy with the behavior policy, R-learning when learning the optimal policy off-policy, and Differential Expected SARSA for reduced variance while maintaining flexibility.

Key Takeaways

Essential Concepts

Average Reward Rate r(π):
The long-run expected reward per time step. Independent of starting state under ergodicity.

Differential Values v(s):
How much better or worse a state is compared to the average. Measures relative quality, not absolute.

No Discounting:
Future rewards not discounted. Suitable when all future time steps matter equally in continuing tasks.

R-Learning:
The workhorse algorithm for average reward. Simultaneously learns r̄ and Q-values.

The average reward setting provides a principled alternative to discounting for continuing tasks. By measuring steady-state performance and relative state quality, it avoids the arbitrariness and numerical issues of the discount factor while remaining theoretically sound for ergodic MDPs.
